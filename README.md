# ТЕХНИЧЕСКОЕ ЗАДАНИЕ: Telegram-бот «Smart Scheduler» (MVP)

## 1. ЦЕЛЬ ПРОЕКТА
Создать систему автоматизации записи на встречи. Бот выступает фильтром: пользователь выбирает слот, а владелец (Админ) подтверждает или отклоняет заявку в один клик прямо из Telegram.

## 2. ТЕХНОЛОГИЧЕСКИЙ СТЕК
- **Язык:** Python 3.10+
- **Библиотека бота:** aiogram 3.x (асинхронность)
- **База данных:** SQLite
- **Интеграция:** Google Calendar API (через Service Account)
- **Среда разработки:** Cursor

## 3. РОЛИ И ПРАВА
- **Пользователь (Клиент):** Любой человек, запустивший бота.
- **Владелец (Админ):** Доступ к модерации и настройкам по `ADMIN_ID`.

## 4. СЦЕНАРИЙ ПОЛЬЗОВАТЕЛЯ
1. **Выбор длительности:** 15, 30, 60 или 90 минут.
2. **Выбор даты:** Список дней на текущую неделю (кнопка «Следующая неделя»). Дни со свободными окнами помечены ✅.
3. **Выбор времени:** Сетка слотов (шаг 30 мин), учитывающая занятость в Google Календаре и «Буфер безопасности». Кнопка «Назад».
4. **Заполнение анкеты:**
    - **Имя:** Текстовый ввод.
    - **Тема:** Текстовый ввод.
    - **Описание:** Текст (может содержать ссылки на Zoom/Meet). Есть кнопка **«Пропустить»**.
    - **Email:** Валидация ввода.
5. **Финал:** Заявка уходит админу, пользователь ждет решения.

## 5. ФУНКЦИОНАЛ ВЛАДЕЛЬЦА (АДМИН-ПАНЕЛЬ)
### А. Модерация заявок
При новой заявке админ получает сообщение:
> 🔔 **Новая заявка!**
> 👤 **Имя:** [Имя пользователя] ( @[username] )
> 📧 **Email:** [email]
> 📝 **Тема:** [тема]
> 📄 **Описание:** [текст или "отсутствует"]
> ⏰ **Время:** 10.02, 14:00 (60 мин)
>
> `[✅ Подтвердить]` `[❌ Отклонить]` `[🚫 В бан]`

### Б. Управление через /admin
- **Таймзона:** По умолчанию `Europe/Moscow`, смена через меню.
- **Рабочие интервалы:** Установка часов (например, 11:00–18:00).
- **Blacklist дат:** Кнопка «Выключить запись на определенный день».
- **Буфер безопасности:** За сколько часов до встречи закрывать запись (например, 3 часа).
- **Broadcast:** Рассылка сообщения всем подтвержденным участникам на конкретную дату.
- **Список ожидания:** Поиск заявок, на которые не был дан ответ.

## 6. ТЕХНИЧЕСКАЯ ЛОГИКА
- **Синхронизация:** Перед показом слотов бот делает запрос `freebusy` к Google API.
- **Таймзоны:** Все даты в БД хранятся в **UTC**. Отображение в боте — согласно настройке `timezone` (по умолчанию МСК).
- **Автоматизация:**
  - Срок жизни заявки — 24 часа (после чего статус `expired`).
  - После нажатия «Подтвердить» бот создает `Event` в Google и добавляет Email клиента в участники (`attendees`).
- **Связь:** В сообщении админу ссылка на `@username` должна быть кликабельной.

## 7. СТРУКТУРА БАЗЫ ДАННЫХ (SQLite)
- **`settings`**: (key, value) — таймзона, часы работы, буфер.
- **`meetings`**: (id, user_id, username, user_name, user_email, subject, description, start_time, duration, status, created_at).
- **`blacklist_dates`**: (date, reason).
- **`users_blacklisted`**: (user_id, banned_at).

## 8. ИНСТРУКЦИЯ ДЛЯ CURSOR
1. Использовать `Service Account` через JSON-файл ключа.
2. Реализовать `FSM` (Finite State Machine) для пошагового сбора данных от пользователя.
3. Разделить код на модули: `handlers/`, `services/google_api.py`, `database/`.

```bash
./scripts/bootstrap.sh
. .venv/bin/activate
cp .env.example .env
python scripts/check_config.py
python scripts/init_db.py
python bot.py
```

## Деплой (VPS + Dokploy) — текущий прод

- **Сборка**: Dokploy → Deploy from Git, Dockerfile в корне репо, образ например `calendar:latest`.
- **Volume**: host-path `/opt/calendar-data` на сервере → mount path `/app/data` в контейнере.
- **Файлы**: положить в `/opt/calendar-data` на VPS: `client_secrets.json`, `token.json`, при необходимости `smart_scheduler.db` (через `scp` или после первого запуска).
- **Env**: `BOT_TOKEN`, `ADMIN_ID`, `CALENDAR_ID`, `GOOGLE_AUTH_MODE=oauth`, `DB_PATH=/app/data/smart_scheduler.db`, `GOOGLE_OAUTH_CLIENT_SECRETS_PATH=/app/data/client_secrets.json`, `GOOGLE_OAUTH_TOKEN_PATH=/app/data/token.json`, плюс `TIMEZONE`, `WORK_START`, `WORK_END`, `BUFFER_HOURS`, `LOG_LEVEL`, `PENDING_TTL_HOURS`, `EXPIRE_CHECK_INTERVAL_SECONDS`.
- **Порты**: не публиковать (бот без HTTP). Replicas: 1, restart: always.

Подробный контекст и карта кода: см. `HANDOFF.md` и `PROJECT_STEPS.md`. План по Mini App (отдельный проект): `MINI_APP_ROADMAP.md`.
