# Troubleshooting: Не вижу изменения после деплоя

## Быстрая диагностика

### 1. Проверьте, что смотрите на главную страницу

**Glassmorphism дизайн применяется только к главному экрану (Home)!**

- ✅ Правильно: Открыли бота → Menu Button → видите экран с "Easy Meet"
- ❌ Неправильно: Вы на экране "Запись встречи" (Booking) или "Мои заявки"

**Как попасть на главную:**
1. Откройте @google_calendar_booking1_bot
2. Нажмите Menu Button (синяя кнопка внизу)
3. Если уже внутри приложения — нажмите "← Назад" несколько раз до главной

---

### 2. Очистите кеш

**В Telegram Desktop/Mobile:**
1. Закройте Mini App полностью
2. Закройте Telegram
3. Откройте Telegram снова
4. Откройте бота и Menu Button заново

**Или:**
- Telegram Desktop: Settings → Advanced → Clear cache
- После очистки перезапустите Telegram

---

### 3. Проверьте Dokploy деплой

**Dokploy может не запускать автодеплой автоматически.**

Проверьте настройки в панели Dokploy:
1. Откройте ваше приложение в Dokploy
2. Перейдите в Git/GitHub настройки
3. Проверьте:
   - [ ] Auto Deploy включен?
   - [ ] Webhook настроен?
   - [ ] Branch = `main`?

**Если автодеплой не настроен:**
- Нажмите "Deploy" вручную в панели Dokploy
- Или настройте webhook в GitHub

---

### 4. Ручной деплой (если автодеплой не работает)

**Вариант A: Через панель Dokploy**
1. Откройте приложение
2. Нажмите "Redeploy" или "Rebuild"
3. Дождитесь завершения (2-3 минуты)
4. Проверьте логи на ошибки

**Вариант B: SSH на сервер (если есть доступ)**
```bash
# Подключиться к серверу
ssh user@your-server

# Найти контейнер
docker ps | grep calendar

# Перезапустить
docker restart <container-id>
```

---

### 5. Проверьте файлы на сервере

**Если есть SSH доступ:**
```bash
# Зайти в контейнер
docker exec -it <container-id> /bin/sh

# Проверить CSS файл
ls -lh /app/dist/assets/

# Должен быть index-ptLJn1Ng.css (9.3 KB)
cat /app/dist/index.html | grep index-ptLJn1Ng.css
```

Если файл старый — значит Dokploy не пересобрал образ.

---

### 6. Проверьте версию в браузере

**Откройте Dev Tools в Telegram Desktop:**
- Mac: Cmd + Alt + I
- Windows: Ctrl + Shift + I

**Проверьте:**
1. **Network tab** → перезагрузите страницу
2. Найдите `index.html`
3. Посмотрите, какие CSS/JS файлы загружаются
4. Должны быть:
   - `index-ptLJn1Ng.css` (новый, 9.3 KB)
   - `index-BN0KwaQH.js` (новый, 252 KB)

**Если загружаются старые файлы:**
- Проблема в кеше Telegram или сервер не обновился
- Очистите кеш (см. пункт 2)

---

### 7. Проверьте что вы видите

**На главной странице (Home) должно быть:**

✅ **Видите это — всё ОК:**
- Заголовок "Easy Meet" (крупный, с градиентом)
- Анимированный градиентный фон (синий/фиолетовый/индиго)
- Две прозрачные "стеклянные" карточки с размытым фоном
- Иконки 🗓️ и 📋

❌ **Видите это — старая версия:**
- Заголовок "Запись встречи"
- Сплошной серый/белый фон
- Обычные белые карточки без эффекта стекла

---

### 8. Webhook GitHub → Dokploy (настройка автодеплоя)

Если автодеплой не работает, настройте webhook:

**В GitHub:**
1. Репо → Settings → Webhooks → Add webhook
2. Payload URL: `https://your-dokploy-url/api/deploy/webhook?token=YOUR_TOKEN`
3. Content type: `application/json`
4. Events: "Just the push event"
5. Active: ✅

**В Dokploy:**
1. Приложение → Settings → Git
2. Скопируйте Webhook URL
3. Убедитесь, что Auto Deploy = ON

---

### 9. Логи Dokploy

**Проверьте логи деплоя:**
1. Dokploy панель → ваше приложение
2. Вкладка "Logs" или "Deploy History"
3. Последний деплой должен быть ПОСЛЕ вашего коммита `1321034`
4. Ищите ошибки:
   - Build errors
   - Docker errors
   - npm errors

**Если деплой старый:**
- Нажмите "Redeploy" вручную

---

### 10. Прямая проверка (curl)

```bash
# Проверьте что сервер отдаёт новый HTML
curl -s https://calendar.vpncfo.ru | grep "ptLJn1Ng"

# Должно вывести строку с index-ptLJn1Ng.css
```

Если не выводит — сервер не обновился.

---

## Решение: Пошаговый план

1. **Сначала:** Убедитесь что смотрите на главную страницу (Home, с "Easy Meet")
2. **Если не главная:** Нажмите "← Назад" до главной
3. **Очистите кеш:** Закройте Telegram полностью, откройте снова
4. **Если не помогло:** Ручной деплой в Dokploy
5. **Если не помогло:** Проверьте логи деплоя
6. **Если не помогло:** SSH на сервер, проверьте файлы
